## 1. 这是什么 / 怎么开

套在编排引擎外面的**两页跳板**：一页跑、一页改。链条**按程序**读 —— 每个程序跑哪几节由它自己的清单 [`orchestrator/apps/<key>/nodes/__init__.py`](../orchestrator/apps/) 决定（[ADR 0005](./adr/0005-per-program-node-chain.md)），界面显示的节点数与名称跟着当前程序变。

| 页 | 左（约 1/5 宽） | 右 |
| --- | --- | --- |
| **运行** | 顶部目标程序多选器；下面步骤列表（序号 = 节点号，等宽，像代码行号），带状态 | 输出日志，顶端常驻「当前步骤 N · 名称 · 状态」 |
| **节点代码** | 同一份步骤列表，**可点击** | 该节点源码，可改，右下角保存 |

设计目标是**随时改、随时跑**：节点 6 失败 → 第 2 页 → 点节点 6 → 改 → 保存 → 第 1 页 → `只跑节点 6`。全程不离开这个窗口。

### 1.1 双击就开（推荐）

双击 [`launcher/gui.bat`](../launcher/gui.bat)。不用开终端、不用记命令；它从自己所在目录往上找仓库根，放在仓库根或 `launcher\` 都能跑。

也可以在命令行里带参数透传：

```bat
launcher\gui.bat              :: 直接开界面（自己弹 UAC）
launcher\gui.bat --dry-run    :: 启动时预勾选 dry-run
launcher\gui.bat --only 8     :: 启动时预选「只跑节点 8」
launcher\gui.bat --no-elevate :: 明确不提权（调试用）
```

`gui.bat` 只做五件事，**决策逻辑一行都不复制**（否则会和 Python 侧漂移，出现「bat 提权了、python 又提权一次」）：

1. **找仓库根**：从 bat 自己所在目录往上逐级找，第一个含 `gui\__main__.py` 的目录就认作仓库根；被挪出仓库树则 `exit /b 5`，绝不瞎猜；
2. `cd` 到仓库根（`python -m gui` 只在仓库根才解析得到 `gui` 包）；
3. 选解释器：优先环境变量 `ONETAP_PYTHON`，否则 `D:\WORKs\Anaconda\python.exe`；
4. 前置检查：解释器不在、或缺 `tkinter`，立刻给一句人话 + `pause`，不让黑窗一闪而过；
5. 启动 `"%PY%" -X utf8 -m gui %*`，参数原样透传，再按退出码提示。

**提权交互**：双击后弹 UAC。点「是」→ 界面开在**另一个进程**里，这个黑窗**立刻关闭**（正常，不是崩溃）。点「否」→ 走降级路径，界面照开但有红横幅、节点 9 无法清理进程，bat 会停 6 秒把这点说清楚。

| 退出码 | 含义 |
| --- | --- |
| `0` | 正常（提权副本接手后父进程也是 0） |
| `3` | UAC 被拒，降级运行 |
| `4` | 导入 GUI 模块失败（顺带打印 `elevate-failed.log` 末尾 40 行） |
| `2` | 解释器或 tkinter 缺失（启动前就拦下） |
| `5` | 找不到仓库根（启动前就拦下） |

⚠️ **`gui.bat` 正文刻意全是 ASCII**。cmd 逐行、按当前代码页解析 bat，`chcp 65001` 只影响它之后的执行 —— 文件里靠前的 UTF-8 中文会被当成 ANSI 拆成碎片（实测报 `'断点式编排' is not recognized as an internal or external command`）。中文提示一律交给 Python 打印。

### 1.2 手动命令

```powershell
cd E:\TOOLS\ScriptsGames\Onetap
& "D:\WORKs\Anaconda\python.exe" -X utf8 -m gui
```

这一条就够了。**GUI 自己弹 UAC 提权**：入口 [`gui/__main__.py`](../gui/__main__.py) 先检查本进程令牌，发现未提权就用 `ShellExecuteW("runas")` 重启一份**提权副本**，父进程随即退出。不需要再手写 `Start-Process -Verb RunAs`。

**为什么是「重启一份新进程」而不是原地提权**：Windows 令牌在 `CreateProcess` 时就定了，运行中的进程**无法**给自己提权，唯一路径就是拉起提权副本。提权发生在 `import tkinter` **之前**，所以不会先闪一个无权限窗口。

提权成功时顶部**没有**横幅；未提权时顶部常驻红色横幅（原文：`⚠ 未提权运行 — 节点 1 将按参数跳过，节点 9 无法终止 ok-ww 进程；超时/失败后需手动清理。`），节点 9 只能跳过清理。

参数：

| 参数 | 说明 |
| --- | --- |
| `--dry-run` | 启动时预勾选 dry-run |
| `--only N` | 启动时预选「只跑节点 N」 |
| `--no-elevate` | **明确不提权**，直接开界面（调试用；或本来就在管理员终端里） |

前两个参数会被**原样带给提权副本**。目标程序多选器**没有**对应启动参数 —— 它是界面上的即时选择，不预置。（命令行串联直接跑 `python -m orchestrator.steps.main --target zmd,ww,nte`；`--target all` / `--target both` 也是全部，`both` 是 2026-10 的历史写法，永久保留。）

**提权失败时不会硬失败**：降级为「未提权但能开」（横幅 + 节点 1 跳过），因为改代码和看日志本来就不需要管理员。控制台会说明原因，并附上**提权副本本该执行的确切命令行**；副本启动异常时还会往仓库根写 `elevate-failed.log`。

### 1.3 自提权的三个静默陷阱（改代码前必读）

「UAC 弹了却没有界面」都属于**静默失效**，不报错：

1. **`ShellExecuteW` 的返回值不是成功判据**：子进程已死时它照样返回 42（>32 即「success」）。所以 [`gui/elevate.py`](../gui/elevate.py) 加了**心跳确认** —— 父进程等副本写出的心跳文件，等到了才算成功；
2. **`lpParameters` 不能含 exe 本身**：exe 走 `lpFile`；拼进参数会让 python 把 `python.exe` 当脚本路径；
3. **本程序自己的参数必须放在 `-m gui` 之后**：python 把 `-m gui` 之前的一切当成**它自己的**选项，`--heartbeat` 会得到 `unknown option` 并以退出码 2 在写心跳前死掉。

`--elevated` / `--heartbeat` 是 `gui/elevate.py` 自己产生、自己消费的**内部**参数，不进 argparse。

## 2. 第 1 页：运行

### 2.1 目标程序多选器（左栏顶部）

一列 **Checkbutton，任意多选**，下面 `全选` / `清空`，顶上 `跟随上次记录（不传 --target）` 开关（默认勾上）。清单顺序与执行顺序一致：**MaaEnd → ok-ww → ok-nte**（用户裁定，MaaEnd 必须排第一；见 [RUNBOOK.md](./RUNBOOK.md) 与 [ADR 0003](./adr/0003-per-program-app-modules.md)）。

| 操作 | 传给 `steps/main.py` | 说明 |
| --- | --- | --- |
| `跟随上次记录` 勾上（默认） | **不传** `--target` | 跟着 `state.json` 里记着的程序走 |
| 只勾 MaaEnd | `--target zmd` | 只跑 MaaEnd（第三目标程序，2026-10-18 接入） |
| 只勾 ok-ww | `--target ww` | 只跑 ok-ww |
| 勾 ok-ww + ok-nte | `--target ww,nte` | **串联**：先后各跑一轮完整链条 |
| 勾上全部三个 | `--target all` | 按清单顺序 **zmd → ww → nte** 串联 |
| 一个都不勾 | —— | **拒绝启动**，清单下方红字告警 |

⚠️ **一个都不勾不按「全部」处理**。省略 `--target` 的语义是「跟随记录」，把「什么都没选」当成「全选」是最容易让人跑错一轮的那种**静默失效**。

⚠️ 「跟随记录」**故意不传** `--target`（而不是传 `ww`）。`main.py` 的 `--target` 是**覆盖**语义：一旦传了，`接着上次` 续跑 ok-nte 时会被悄悄改回 ok-ww。跟随中直接勾一个程序 = 想手动选，界面会**自动关掉跟随**。运行期间选择器整体锁住（改了也不会生效）。

**每行行尾的进度点**是该程序**正在跑的那一轮**的进度，与勾选无关：

| 显示 | 含义 |
| --- | --- |
| `○` | 这个程序还没有任何节点状态 |
| `▶ 3/8` | 跑着，该程序清单里 8 个节点已有 3 个终态（分母 = 该程序节点数） |
| `3/8` | 部分完成但没在跑（例如上一轮停在中途） |
| `✓ 8/8` | 全过 |
| `✖ 2/8` | 有失败 / 超时 |

**点目标行**（不是勾选框）→ 下方步骤列表切到该目标的状态，列表上方显示 `步骤状态：ok-ww`；再点一次回到「跟着正在跑的那个走」。串联时每个目标各有独立的一套节点状态，这是唯一能来回看的地方。切换目标时**整列重建**：节点数、label、★ 标记都取**该程序自己的清单**（不是三者的并集）。

⚠️ 选中多个目标时，各轮日志落在**不同子目录**（`<run-dir>/zmd`、`<run-dir>/ww`、`<run-dir>/nte`），否则节点号相同、`step8.log` 会互相覆盖。任一程序失败**不中断**另一程序。

### 2.2 步骤列表

每行：

```
 1   提权检查              ○     <- 序号(等宽) 名称 状态点
     未运行
```

状态点：`○` 未运行 · `▶` 运行中（蓝底） · `✔` 已完成（绿） · `✖` 失败（红） · `⏱` 超时（橙） · `–` 跳过（灰）。

**列表内容来自当前显示的那个程序的清单**（§2.1 点选的那份）。同一个节点号在不同程序可以有不同的 label —— 例：节点 5 在 ok-ww / ok-nte 是「等待窗口就绪」，在 MaaEnd 是「等待窗口就绪 + 等自我更新」；节点 8 三个程序都有，但实现文件不同。★ 标记表示该节点有**程序专属参数**。

**第二行是摘要，不是证据。** 它来自节点写进 `state.json` 的 `notes`，界面上**截断到 26 个字符**（超出以 `…` 结尾）；标签另设 `wraplength=200` 兜底，再长的 note 也只会折行，**不会把左栏撑宽**（[`gui/app.py`](../gui/app.py) 的 `NOTE_MAX` / `NOTE_WRAP`）。

节点 8 的完成汇报原文常上百字符（七个成功任务 + 跳过项 + 终止标记），完整那句在两处：右侧日志里的 `[结果] ...` 行（`frameops.finish()` 打印的**全量** detail），以及 `<run-dir>/<target>/state.json` 的 `steps["8"].notes` / `result_detail`。**界面短、证据全**。

### 2.3 顶端「当前步骤」与日志

右侧日志顶端常驻：

```
当前步骤 6 · 抓首帧并校验 · 运行中
```

它来自**轮询 `<run-dir>/state.json`**，不是解析日志文本 —— 节点在进入/离开时会写这个文件（`RunState.begin()` 先写 `running` 并落盘），所以指示**准确**，不受日志措辞变化影响。串联时还会带目标名（`ok-ww · 6 · …`）。

日志配色：

| 颜色 | 含义 |
| --- | --- |
| 蓝色加粗 | `[节点 N]` / `[主控]` |
| 青色 | `[OK]` / `[结果]` |
| 黄色 | `[警告]` / `[!!]` / `跳过` |
| 红色 | `[中止]` / `[异常]` / `FAILED` / `失败` |

### 2.4 控制条（底部）

从右到左：`▶ 运行编排`、`■ 停止`、`dry-run`、**目标摘要**、`只跑节点 N`、`接着上次`。

| 控件 | 作用 |
| --- | --- |
| ▶ 运行编排 | 起子进程跑 `steps/main.py` |
| ■ 停止 | **整树终止** `taskkill /T /F`（见 §4） |
| dry-run | 传 `--dry-run`（不点击、不杀进程） |
| 只跑节点 | 传 `--only N` |
| 接着上次 | 传 `--resume` |

控制条上的**目标摘要**是只读的（`目标：ww,nte` / `目标：跟随记录`），真正的选择在左栏顶部 —— 运行中忘了自己勾了什么看一眼这里。

## 3. 第 2 页：节点代码

点左侧任一节点 → 右侧载入**该节点在当前程序清单里指向的文件**：共用节点是 `orchestrator/steps/common/stepN_*.py`，专属节点是 `orchestrator/apps/<key>/nodes/stepN_*.py`。

编辑器（[`gui/editor.py`](../gui/editor.py)）：行号 · 语法高亮 · 撤销（`Ctrl+Z`） · 自动缩进（回车保持缩进，`:` 结尾自动加一级） · `Ctrl+S` 保存。

| 按钮 | 作用 |
| --- | --- |
| 保存 | 原子写入磁盘（临时文件 + `os.replace`），保留原文件的结尾换行习惯 |
| 放弃修改 | 重新从磁盘载入 |

⚠️ **只改这一份文件就是改了这一节的行为**。节点之间只通过 `state.json` 通信、不共享内存，所以改节点 6 不会影响节点 7。

### 两条硬规则

1. **运行中禁止保存。** 编排跑着时点保存会被拒绝并提示 —— 正在运行的节点进程可能正读到半个文件。先停止，或等这轮跑完。
2. **保存后下次运行生效。** Python 不能热重载运行中的函数；要看到效果得重跑该节点（第 1 页的「只跑节点」正好干这个）。

### 例：节点 6 身份校验失败

```
当前步骤 6 · 抓首帧并校验 · 失败
  [INV-12] 身份校验失败：侧栏图标 score=0.4074 < 0.95
```

1. 切「节点代码」→ 点 `6 抓首帧并校验`；
2. 改 `step6_first_frame.py`；
3. **保存**；
4. 回「运行」→ 勾 `只跑节点` 选 `6` → 点运行。

不必重启目标程序，也不必重跑节点 1~5。（上面是 ok-ww 的例子：改的是共用文件 `steps/common/step6_first_frame.py`。MaaEnd 的 5/6 是专属节点，文件在 `apps/zmd/nodes/`，同理只改那一个文件。）

## 4. 停止为什么是强制的

[`orchestrator/steps/main.py:278`](../orchestrator/steps/main.py#L278) 用 `subprocess.run` **逐节起子进程**，主控与节点是父子关系。

⇒ 只杀主控会留下**孤儿节点进程继续操作真实鼠标** —— 界面上显示「已停止」，而屏幕上鼠标还在自己动。所以停止走 `taskkill /PID <主控> /T /F`，`/T` 杀整棵树、`/F` 强制（节点在抓帧/等待循环里不响应温和终止）。见 [`gui/runner.py`](../gui/runner.py) 的 `stop()`。

界面上点停止会先弹确认框说明这一点。

## 5. 它刻意不做的事

| 不做 | 原因 |
| --- | --- |
| 不 import 任何 `orchestrator` 业务模块 | GUI 是跳板：某个节点文件语法坏了时，你必须还能打开 GUI 去修它。[`gui/chain.py`](../gui/chain.py) 用 `ast` 静态解析各程序的 `apps/<key>/nodes/__init__.py`（清单就是磁盘上的那份，不 import），[`gui/targets.py`](../gui/targets.py) 同样静态读 `programs.py`；启动时逐程序与磁盘**比对并警告**，不崩溃 |
| 不放帧预览 | 抓图肉眼复核在 `logs/runs/<run>/shots/`，用资源管理器看更快。要把预览加回来很简单（`PIL.ImageTk`，Pillow 已在依赖里） |
| 不做 git 集成 | 这个仓库**不是** git 仓库。`git init` 是你的决定，不是 GUI 偷偷做的事 |

> **自提权已不再排除**。早期版本刻意不自提权（靠 `Start-Process -Verb RunAs` 手动来），现在入口会自己弹 UAC（§1.2）。提权失败仍**不硬失败**：降级开界面，改代码看日志不该被权限卡住。

## 6. 文件结构

| 文件 | 职责 |
| --- | --- |
| [`gui/__main__.py`](../gui/__main__.py) | 入口：令牌检查、`ShellExecuteW("runas")` 自提权、参数解析 |
| [`gui/elevate.py`](../gui/elevate.py) | 提权副本的拉起与心跳确认（内部参数 `--elevated` / `--heartbeat`） |
| [`gui/app.py`](../gui/app.py) | 两页界面（`ttk.Notebook`）、日志、步骤行、目标多选器 |
| [`gui/chain.py`](../gui/chain.py) | 按程序读节点清单（`ast` 静态解析 `apps/<key>/nodes/__init__.py`）+ 逐程序漂移校验 |
| [`gui/targets.py`](../gui/targets.py) | 目标程序清单（`ast` 静态读 `programs.py`，读不出回落兜底并告警） |
| [`gui/editor.py`](../gui/editor.py) | `CodeEditor`：行号 + 增量高亮 + 原子保存 |
| [`gui/runner.py`](../gui/runner.py) | 子进程驱动 + `state.json` 轮询 + 整树终止 |

**零新增依赖**：GUI 只用标准库（`tkinter` / `queue` / `subprocess` / `json`）；帧预览要用到时可直接用已在依赖里的 Pillow（§5）。

⚠️ **清单只有一份，读取器有两套**：链条由各程序的 `apps/<key>/nodes/__init__.py` 声明，[`gui/chain.py`](../gui/chain.py) 用 `ast` 静态读它，[`orchestrator/steps/main.py`](../orchestrator/steps/main.py) 运行时经 `orchestrator/steps/chain.py` 读**同一份文件** —— 不再有第二份 `STEPS`/`CHAIN` 要手工同步。GUI 启动时仍逐程序比对清单与磁盘并告警（§7.2）。目标清单同理：`gui/targets.py` 的 `FALLBACK` 与 `orchestrator/programs.py` 的 `ALL`。

### 7.4 实现过程中修掉的两个真实缺陷

都不是「测试写错」，是代码本身的问题。

**（1）`_apply_tags` 是 O(n²)，导致自检挂死。** 第一版判断「某位置是否在注释里」用的是对 `comment_spans` 线性扫描：

```python
def in_comment(s):
    return any(a <= s < b for a, b in comment_spans)   # ← 每个匹配都扫一遍
```

`_apply_tags` 里每个正则匹配都调它一次 ⇒ 整体 O(n²)。400 行文件就能让自检**永久挂住**（不是慢，是不返回）。**修法**：在已排序的 span 上二分（`bisect_right`）。修完 2000 行全量 965ms、增量 8ms。

**（2）自检里的模态对话框死锁。** `on_save()` 在「运行中」会调 `messagebox.showwarning` —— 模态对话框，无头环境没人点「确定」，自检**永远挂在那里**。**修法**：自检里把 `gui.app.messagebox` 换成不弹窗的桩。这是**测试**的坑，不是产品缺陷；教训是**无头测 GUI 必须先把所有模态对话框打桩**。

### 7.5 停止语义的对照实验

第一版自检用 `os.kill(pid, 0)` 判断进程是否真的被杀，**误报为失败**。单独做了对照（[`_probe_gui2_stop.py`](../probe/_probe_gui2_stop.py)）：

```
起子进程 pid=64996
  tasklist 命中（杀之前）: True
  Popen.poll()            : None
stop() -> 已终止进程树 (pid 64996)
  Popen.poll()            : 1        ← 已退出
  tasklist 命中（杀之后）  : False    ← 系统视角确实没了
```

⇒ `taskkill /T /F` **工作正常**。Windows 上 pid 在 `Popen` 回收前仍可能被 `os.kill(pid,0)` 命中，所以判据应当用 `Popen.poll()` / `tasklist`。

## 9. 排障

| 症状 | 先看 |
| --- | --- |
| 顶部红条 / 节点 9 报「未提权，跳过清理」 | 自提权没成功，已降级运行。看控制台的提权提示（含副本本该执行的确切命令）；想手动提权就开管理员终端重跑（§1.2） |

| 保存按钮是灰的 | 没有改动（或点的是不存在的文件） |
| 改了代码没生效 | 保存只在**下次运行**生效；用「只跑节点 N」重跑 |
