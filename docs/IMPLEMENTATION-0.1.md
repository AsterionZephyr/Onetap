## 2. 相对文档的三处实测修正

### 2.1 节点 3「跨过第一层」已删除

文档把它写成「唯一一个在校验缺省状态下点击的动作」，并围绕它讨论了「不点也要等 21 秒」。
本次实机复核（`ok-ww` 日志）证明**不存在这道关卡**：

```
MainWindow:show startup version change on about tab    ← 界面已在「关于」页
MainWindow:Window has fully displayed
MainWindow:MainWindow showEvent Kill Launcher After Start
```

今天 8 次启动（00:00 / 02:02 / 02:25 / 02:44 / 03:08 / 12:44 / 13:47）**没有一次**停在
「检查更新」；`ok-ww.exe` 内部 `Scheduling auto-start for 'ok-ww' in 10 seconds` 自行启动第二层。
首次启动可能停在**应用更新页**（本次实测到），但那只是停在哪一页，**第二层同时在运行**。

⇒ 删除节点 3。`ok-ww.exe` 静默跑到底，不再有「校验缺省状态下点击」这个动作。

### 2.2 锚点改为可见锚点组合（ADR 0002）

见 [ADR 0002](./adr/0002-anchor-combination-and-joint-uniqueness.md)。要点：
「每日任务」四字在**面板收起态**有 2 个候选，且**最高分那个是错行**
（0.9991 落在「多账号每日任务」行，对行只有 0.9225）。改用「日历图标 + 每日任务」
（`2_ww.png[:, 9:72]`）后实测唯一。

### 2.3 完成判定需要「退出通知」资产

横幅 `已完成：📅 每日任务 已运行: 0h 1m 32s` 在**正常完成态**与**等待状态**下**文案完全相同**。
唯一的区分图元是通知「成功执行任务, 正在退出游戏和App!」，它只在正常完成时出现。

```
python -m orchestrator.selftest
```

| 样本 | 身份校验 | 行定位 |
| --- | --- | --- |
| 任务页（面板展开）1875x1250 | ✅ 1.0000 | ✅ 锚点 0.9471 @ (232,570)，候选数 **1**，按钮 (1734,589) |

### 3.3 负向对照（证明校验器**真的会失败**）

| 编号 | 输入 | 期望 | 实测 |
| --- | --- | --- | --- |
| N-1 | 上下翻转的帧（侧栏图标不在原位） | 身份校验失败 | ✅ 失败：score=0.7574 < 0.95 |
| N-2 | 纯黑帧 | 内容校验失败 | ✅ 失败：均值 RGB (0,0,0) |
| N-3 | 用被否决的「仅四字」锚点 | 暴露歧义 | ✅ 2 个候选：**0.9991@(310,990)**、0.9225@(257,570) |

**N-3 是最有价值的一条**：它用程序复现了 ADR 0002 的裁决依据，且证明这个歧义**不是一次性

## 4. 当前唯一的功能缺口

**`exit_notice` 资产未采集。** 后果：框架**无法判定「正常完成」**，只能以「超时」收场
（退出码 4）。程序会在启动时明确打印这个缺口，不会假装没事。

采集方法：在任务正常完成的那 5 秒窗口内抓一帧，裁出通知条，登记进 `assets.json`。
可复用 `probe/watch_autoclose.py` 或 `probe/observe_v2.py`。

## 6. 提权后怎么跑

```
# 1) 以管理员身份启动终端，确认提权自检通过
python -m orchestrator --dry-run          # 不点击，只看校验

# 2) 让 ok-ww 停在任务页，再跑一次 dry-run，可单独验证锚点定位
python -m orchestrator --dry-run --no-launch

# 3) 实跑（会真正点击、等待、必要时清理）
python -m orchestrator
```

退出码：`0` 完成 / `2` 环境前提不成立 / `3` 不变量被破坏（已停手）/ `4` 超时 / `5` 未预期异常。

日志与抓图落在 `logs/` 与 `logs/shots/`。**抓图必须肉眼复核**（HANDOFF §9 第 5 条）：
只靠分数与亮度会漏掉「抓到的是别的窗口」。
