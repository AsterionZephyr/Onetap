「只保留最近十轮」的策略会被程序自动清理（策略见 `docs/RUNBOOK.md` §11），
所以「目录还在不在」不能说明「这一轮跑没跑过」—— **本表才是记录**。

- 范围：**2026-10-23 整理之前**磁盘上的 75 个目录。
  之后新增的轮次不进本表，它们的记录就是 `logs/runs/` 里还留着的目录本身。
- 「程序 / 结果」取自各目录 `state.json`：通过数 / 总节数（只数非 `running` 的节），
  未全部通过时列出未通过的节点号。串联运行按程序分列。
- 「被引用」= `docs/` 里出现过这个 run-id 的文档与次数。**目录被删不改正文**：
  文档里的 run-id 是历史叙事（「这一轮抓到 19 张帧」），把正文改成「已清理」等于改写历史。
- 重新生成（不含引用列）：`python -X utf8 -m orchestrator.logretention --index`。
- **这一条是有意的**：2026-10-23 之后的轮次按上面第一条规则**不进表**。要查那些轮次，看
  [HISTORY.md](./HISTORY.md) 的对应小节（例：第 9 轮的 `run-20261023-050007` / `run-20261023-052839` /
  `run-20261023-055917`），或直接看还留在 `logs/runs/` 里的目录。
